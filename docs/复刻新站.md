# 如何复刻一个新站点

> 基于第四站 **OpenHot（开源热点）** 的真实建站过程。案例日期 2026-10-12，模板站 `AcadHot`。
>
> **依据标注**：`[SPEC]` = 出自 `E:\NEWS\OPENHOT-SPEC.md`；`[实测]` = 本次逐字读文件或实际跑命令验证过；`[未验证]` = 本环境无法验证，已注明原因。
> 命令标注 **PS**（Windows PowerShell）或 **bash**（Git Bash / WSL）。路径一律写 Windows 绝对路径。

## 0. 这份手册解决什么

**把 AIHOT 框架复制成一个新的行业站，不改框架代码。**

框架本身（`apps/`、`packages/`）一行都不用动 `[SPEC]` §10。新站自己的东西全在两个目录 `[实测]`：`site/`（站名文案、品牌、条款页、根目录固定文件、更新日志）和 `industry/`（分类标签、主题、示范信源、九个提示词、门槛）。三种采集器 `web_list` / `json_list` / `rss` 已覆盖全部需求形态 `[SPEC]` §10。

**最重要的一条**：§3 的十步流程里，**第 9 步「构建」必须在第 7、8 步「定制」之后**。顺序反了，界面会显示旧行业的分类而站名却是新的 —— 最容易踩、代价最大的一次返工 `[SPEC]` §11.5 坑 6。

## 1. 开工前必须问使用者的 5 件事

> `AGENTS.md` L9 原话：「**这些事要问使用者本人，不要替他决定：站名；要盯哪些信源；什么消息重要、什么是噪声；分类怎么分；条款和隐私说明的内容（`site/pages/` 是模板，上线前需要他本人确认）。**」`[实测]`

共同点：**它们是行业判断，不是技术判断**。技术上都能改，但改错了没人能替你发现 —— 站会正常跑起来、正常出日报，只是内容不是你想要的。等跑了一周才发现「分类分错了」，前面所有采集和评分数据都要重来。

**提问方式**：一次问完 5 条，**给选项，不要开放式提问**。使用者是产品经理、非技术，开放式问题会得到「你看着办」，等于没问。

### 1.1 站名

- **为什么不能替他决定**：站名进导航、页面标题、分享图、RSS、MCP 工具名、结构化数据，是**上线后最贵的一项**。`mcpPrefix` 一旦有人接入就不能改 `[实测]` `docs/customize.md` L23。
- **要提供什么选项**：三个候选（形如 `X热点` / `X日报` / `X观察`）；说明站名会同时决定 `subject`（行业词）→ 页面上的「**X 日报**」「全部 **X** 动态」。明确问一句「**将来会开放给别人接 MCP 吗？**」会的话 `mcpPrefix` 要一次定死。提醒：不要用 AIHOT 的名字和 Logo `[实测]` `AGENTS.md` L38。
- **案例答案** `[SPEC]` §2：站名「开源热点」，`subject` = 「开源」，`mcpPrefix` = `openhot`。

### 1.2 盯哪些信源

- **为什么不能替他决定**：信源决定内容基本盘，而且**每加一个源都要单独验证能不能抓**（字段路径、要不要代理、配额）。替他选 = 替他承担「抓不到」的风险。
- **要提供什么选项**：一张**已实测可用/不可用清单**（照抄 `E:\NEWS\.verify\SOURCE-FACTS.md`），让他勾。每条源标注三件事：**采集器类型**、**要不要代理**、**配额**。明确告诉他**信源不是一次定死的** —— 后台「信源」页能随时新建、试抓、调频率、暂停 `[实测]` `docs/customize.md` L62。提醒成本：X 账号要 SocialData、公众号要极致了，都**按请求计费** `[实测]` `docs/customize.md` L76。
- **案例答案** `[SPEC]` §5：GitHub Trending（`web_list`）、GitHub Search ×2（`json_list`）、GitHub Releases Atom（`rss`）、mshibanami 镜像（`rss` 降级备份）、HN Algolia（`json_list`，需代理）、Hugging Face models/datasets（`json_list`）、Lobsters（`json_list`）、Reddit（`rss`，需代理 + 自定义 UA）。

### 1.3 什么算重要、什么算噪声

- **为什么不能替他决定**：这是**评分提示词**（`selection-score.md`）的全部内容，决定「选得准不准」。框架默认那套是 AIHOT 在 AI 领域调出来的，换行业必须换 `[实测]` `docs/customize.md` L101。
- **要提供什么选项**：**两边各给例子让他确认**，不要让他从零想。重要侧问「这类消息出来，你希望它一定上日报吗？」；噪声侧问「这类消息出来，你希望它**永远别出现**吗？」。给他看噪声机制在哪一层生效 —— **能在采集层丢的，就别放到模型层**（省钱）。
- **案例答案** `[SPEC]` §4：噪声用 `config.ingestNoiseFilter.dropMarkersTitleOnly` 在**采集层**丢弃 `awesome ` / `Awesome ` / `面试` / `interview` / `leetcode` / `刷题` / `dotfiles` / `中文翻译` / `翻译版`。
  **关键**：只用 `dropMarkersTitleOnly`（只匹配标题），**不要用 `dropMarkers`**（全文匹配），否则会误杀正文里提到这些词的正常项目 `[SPEC]` §4。

### 1.4 分类怎么分

- **为什么不能替他决定**：分类的 `key` 会进网址和接口（`/all?category=`、`/feed/category/<key>.xml`），**上线后不要改** `[实测]` `docs/customize.md` L49。改一次 = 所有外链和历史 RSS 全断。
- **要提供什么选项**：让他**先说 5 个**，你补剩下的（案例就是这么做的：用户选 5 个，agent 补 3 个 `[SPEC]` §3）。对每个分类额外问一句边界：**「这一类里，什么不算？」** —— 这句会变成 `CATEGORIES[].guide` 的「把 X 归 Y」部分，是结构化模型唯一的收录边界依据 `[SPEC]` §11。提醒数量 **6–10 个**：太少筛选没意义，太多首页排不下。
- **案例答案** `[SPEC]` §3：8 个分类，分 4 个 `section`。用户选 `dev-tools` 开发工具 / `cool-repos` 社区新奇仓库 / `security-privacy` 安全与隐私 / `web-frontend` Web 与前端 / `infrastructure` 基础设施；agent 补 `data-database` 数据与数据库 / `languages-runtime` 编程语言与运行时 / `models-datasets` 模型与数据集。

### 1.5 条款与隐私说明的内容

- **为什么不能替他决定**：`site/pages/terms.md` 和 `privacy.md` **现在是模板**，是法律文本，上线前需要他本人确认，必要时请专业人士看 `[实测]` `docs/customize.md` L125。
- **要提供什么选项**：只问三个具体问题，不要让他读全文：
  1. **信源全文能不能在站内展示？** 默认**关**（只展示摘要 + 原文链接）。只有来源明确允许时才开 `[实测]` `AGENTS.md` L33。
  2. **全文 RSS 能不能带正文？** 默认**关**，且只在站内也展示全文时才生效 `[实测]` `docs/customize.md` L74。
  3. **对外联系邮箱填什么？** 填了会写进 `llms.txt` 和给 Agent 的使用说明 `[实测]` `docs/customize.md` L26。
  提醒：`POLICY.terms.license` 是「讲清哪些用途要先取得授权」的那段话 `[实测]` `docs/customize.md` L33。
- **案例做法** `[实测]`：`industry/sources.json` 里 16 个信源全部**没有** `site_fulltext` / `syndicate_fulltext` 字段 → 全走默认关。

## 3. 十步流程

> **执行顺序不能变。第 7、8 步（定制）必须在第 9 步（构建）之前。** 理由见 §4 坑 6。

### 第 1 步 · robocopy 复制模板站

```powershell
# PS
robocopy E:\NEWS\apps\AcadHot E:\NEWS\apps\新站名 /E /XD node_modules .git .data data logs .claude build dist /XF *.log
```

**为什么**：
- `/XD node_modules` **必须**：`node_modules\@aihot\*` 是 **Junction**（目录联接），复制它会复制出一堆指向旧站的链接 `[SPEC]` §6.7 `[实测]`。
- 排除 `build` **同样必须** —— 否则会带着模板站的**构建产物**过去，那是旧行业的界面 `[SPEC]` §6.7。
- **保留 `.github`**：不要把它加进 `/XD` `[实测]` 目标站 `.github` 存在。
- `.data/` `data/` `logs/` 在 `.gitignore` L8 / L19 / L20 里，是运行时产物 `[实测]`。

**怎么验证**（`True` / `False` / `False`）：

```powershell
# PS
Test-Path E:\NEWS\apps\新站名\.github
Test-Path E:\NEWS\apps\新站名\node_modules
Test-Path E:\NEWS\apps\新站名\apps\web\build
```

> `[未验证]` `/XD` 里的 `.claude` 来自本次任务书要求；`[SPEC]` §6.7 只明确了 `node_modules` 和 `build`。

**为什么**：主库给站点用，`_test` 库给 `npm test` 用。**库名必须以 `_test` 或 `_ci` 结尾**，测试自己会建库并迁移，账号要能建库 `[实测]` `AGENTS.md` L20。

### 第 3 步 · 生成 `.env`

```powershell
# PS
cd E:\NEWS\apps\新站名
node scripts/init-env.ts --llm-key <你的 LLM API Key>
```

**为什么**：
- **绝对不要先 `Copy-Item .env.example .env`** —— `init-env.ts` 会**拒绝覆盖已存在的 `.env`**，直接报错退出 `[SPEC]` §6.5 `[实测]`：

  ```
  .env 已经存在，没有覆盖。要重新生成，先把它改名或删掉。
  ```
  （`[实测]` `scripts/init-env.ts` L6–L7。**skill 里「先复制 .env.example」那一步是错的** `[SPEC]` §6.5。）
- **`SESSION_SECRET` / `IMG_PROXY_SIGN_SECRET` / `ADMIN_PASSWORD` 绝不允许跨站共享**，必须由 `init-env.ts` 新生成 `[SPEC]` §6.6。

**怎么验证**：三行都必须有非空值，且与模板站**不同**。

```powershell
# PS
Get-Content E:\NEWS\apps\新站名\.env | Select-String '^(SESSION_SECRET|IMG_PROXY_SIGN_SECRET|ADMIN_PASSWORD)='
Get-Content E:\NEWS\apps\AcadHot\.env | Select-String '^SESSION_SECRET='
```

### 第 4 步 · 补 `.env` 里 `.env.example` 没有的 7 个键

```ini

WEB_PORT=3030
API_PORT=3031
API_BASE_URL=http://127.0.0.1:3031
AIHOT_DATA_DIR=E:/NEWS/apps/OpenHot/data

EGRESS_PROXY_URL=http://127.0.0.1:7890
```

**为什么**：`.env.example` 里这些键是**注释掉的**（`# DATABASE_URL=...`）`[实测]`。本机跑必须显式打开，否则会去连默认的 `5432`。

**怎么验证**（无输出 = 全齐）：

```powershell
$have = Get-Content E:\NEWS\apps\新站名\.env | Where-Object { $_ -match '^[A-Z_]+=' } | ForEach-Object { ($_ -split '=')[0] }
```

`[实测]` 本案例 `.env` 共 **22 个键** = `.env.example` 里的 15 个（`SITE_URL` `ADMIN_PASSWORD` `SESSION_SECRET` `IMG_PROXY_SIGN_SECRET` `POSTGRES_PASSWORD` `LLM_BASE_URL` `LLM_API_KEY` `LLM_MODEL` `LLM_EXTRA_JSON` `FEISHU_CONTENT_PUSH_ENABLED` `FEISHU_INTERNAL_ENABLED` `TRUST_PROXY` `INDEXNOW_SUBMIT_ENABLED` `COLLECT_ENABLED` `MODEL_CALLS_ENABLED`）+ 上面 7 个。

### 第 7 步 · 定制 `site/` 和 `industry/`

**这是整个流程里最花时间、最需要使用者输入的一步。**

#### 7.1 先定 `industry/taxonomy.ts`（**权威**）

**顺序铁律：先定 taxonomy，再改提示词。** 理由见 §4 坑 3。

## 4. 十个坑


> 全部来自 `[SPEC]` §11.5 的实测记录（**坑 1–10 与 SPEC 一一对应**；SPEC 该节标题仍写「三个坑」，是没更新的旧标题）。**这是本手册最重要的一节。**



### 坑 1 · 报告名牌是字形路径，不跟随 `subject`，必须重新生成

**症状**：改了 `site.ts` 的 `subject`，站名、日报标题都对了，**但日报/周报/月报页顶部的报头字还是旧行业的**（比如还是「学术日报」）。

**根因**：`site/brand/nameplates/*.svg` **不是文字，是 SVG 字形路径**。它由 `scripts/nameplates.ts` 把 `SITE.subject` 渲染成 `<path>` 存进文件。运行时只是把 SVG 贴到页面上，不会重新渲染文字 —— 所以改 `subject` 对名牌**零影响** `[SPEC]` §11.5 坑 1。

**怎么发现**：**必须用 SHA256 比对，不能用字节数，也不能用 viewBox 宽度**。
`[SPEC]` §11.5 坑 1 原文：「『学术』和『开源』都是 2 个全宽汉字，宽度可能完全相同（都是 891.5），字节数也可能撞（4222 vs 4222）。只有哈希能区分。」

**怎么避免**：改完 `site.ts` 的 `subject` 立刻按 §3 第 8 步重跑生成器，再用 §6.5 的 SHA256 命令逐条比对 —— 四个 SVG 与模板站**必须两两不同**。

### 坑 2 · GitHub Search 的日期硬编码在 URL 里，框架没有动态日期机制

**症状**：站跑了几个月，「新项目」榜单上全是几个月前的老仓库。信源抓取正常、没有报错。

**根因**：`json_list` 的 `url` 是**静态字符串**，框架**没有任何动态 URL / 日期插值机制** `[SPEC]` §11.5 坑 2：

| 机制 | 实际作用 | 为什么帮不上忙 |
|---|---|---|
| `windowVar` | 只用于 `mode: "html_window_var"` | 从 HTML 抠 `window.X = {...}`，**与 API URL 无关** |
| `publishedAfter` | 只在**采集后**过滤 | 改不了请求 URL |
| `renderTemplate` | 只处理 `urlTemplate` 的 `{path}` / `{raw:path}` | 作用在**返回结果**上，不是请求上 |

`[实测]` 佐证：`renderTemplate` 定义在 `packages/backend/src/sources/json-list.ts` L30，注释写明 `"{path}" → encoded value, "{raw:path}" → raw value`；调用点在 **L181**，是**拿到 item 之后**才渲染的。

**怎么发现**：

```powershell
# PS —— 找出所有写死日期的信源 URL
Select-String -Path E:\NEWS\apps\新站名\industry\sources.json -Pattern 'created:>|pushed:>|created_at_i>NOW'
```

`[SPEC]` §5 记录的形态：

```
https://api.github.com/search/repositories?q=created:>2025-06-01+stars:>500&sort=stars&order=desc&per_page=20
```

**怎么避免**：
- **承认它是技术债**，写进文档告诉使用者：**每隔几个月要人工更新一次日期** `[SPEC]` §11.5 坑 2。
- 降低影响面：让 **Trending 源（实时）承担新项目发现主力**，两条 Search 源只作补充 —— 所以这个债可以接受 `[SPEC]` §11.5 坑 2。

### 坑 3 · 提示词的 `itemType` 键名与 `taxonomy.ts` 的 `ITEM_TYPES` 强耦合

**症状**：模型输出的内容类型**落不进白名单**，结构化结果被丢弃或降级。

**根因**：`industry/prompts/` 里有两份文件逐字列出了 `ITEM_TYPES` 的键名，与 `industry/taxonomy.ts` 的 `ITEM_TYPES` **必须完全一致**。改一边不改另一边就对不上 `[SPEC]` §11.5 坑 3。

### 坑 7 · `start-all.ps1` 不会把信源写进数据库，必须手动跑 `seed.ts`

**症状**：站点启动完全正常——端口在听、首页返回 200、所有 `.err` 日志是 0 字节、界面上的分类和站名全对——但数据库里 `sources` 表是空的（0 行），站点永远不会产出任何内容。别的站有 18–32 个信源，新站是 0。

**根因**：`industry/sources.json` 只是**种子文件**，真正被 worker 读取的是数据库的 `sources` 表。把 `sources.json` 灌进数据库的是 `scripts/seed.ts`，而 **`start-all.ps1` 里根本没有 seed 这一步**（`Select-String 'seed' start-all.ps1` 命中 0 处），`package.json` 里也只有 `db:migrate`、没有 `db:seed`。所以「复制模板 → 改 sources.json → 启动」这条路径走到最后，数据库仍然是空的。

**怎么发现**：用 SQL 数各站的信源数对比：

```sql
select count(*) from sources;
```

新站 0，兄弟站 18/21/32。**端口绿 + 页面 200 + 日志干净，三个全绿也仍然可能是个永远不产出内容的空站。**

**怎么避免**：建站流程里加一步，在首次启动后立刻执行：

```powershell
cd <新站目录>
node --env-file=.env scripts/seed.ts
# 期望输出：sources: N added, 0 already there
```

`seed.ts` 是幂等的（`ON CONFLICT (id) DO NOTHING`），重复跑不会覆盖已有行，也不会报错。

**验证**：

```sql
select count(*) filter (where enabled) as enabled, count(*) as total from sources;
```

两个数字都应该等于 `sources.json` 里的信源条数。之后再确认有内容产出：

```sql
select count(*) from articles;
```

**注意**：因为 `seed.ts` 用的是 `ON CONFLICT DO NOTHING`，**它只新增、不更新**。以后改了 `sources.json` 里已有信源的字段（比如换 URL、改抓取间隔），光跑 `seed.ts` 是**不生效**的，必须直接 `UPDATE` 数据库那一行。数据库里的行才是运行时真正生效的值，`sources.json` 是「种子 + 文档」。

### 坑 8 · HN Algolia 的 `numericFilters=created_at_i>NOW-86400` 是无效语法，稳定 400

**症状**：`open-hn-frontpage` 稳定返回 HTTP 400，信源的 `last_error` 是：

```
{"code":400,"message":"Invalid syntax for numeric condition:created_at_i>NOW-86400"}
```

**根因**：`numericFilters` 只接受「字段 + 比较符 + 具体数值」，**不支持 `NOW-86400` 这类相对时间函数** `[SPEC]` §11.5 坑 8。

**怎么发现**：**探了八个变体才敢下结论** ——

| 变体 | 结果 |
|---|---|
| `created_at_i>NOW-86400,points>50` | **400** |
| 同上但 `>` 写成 `%3E` | **400**（报错一字不差 ⇒ **排除编码问题**） |
| 只有时间 `created_at_i>NOW-86400` | **400** |
| 只有 `points>50` | 200，但语义变成**全历史**（top1 6015 分） |
| 换算成绝对 epoch | 200，可用但**每天要重算** |
| 完全不带 `numericFilters` | 200，但 top1 是历史最高分 |
| `search_by_date` + 绝对 epoch + points | 200（47 条，top1 210 分/1h）✅ |
| **`tags=front_page&hitsPerPage=50`** | **200，30 条，top1 874 分 18 小时前** ✅ 采用 |

**怎么避免**：用

```
https://hn.algolia.com/api/v1/search?tags=front_page&hitsPerPage=50
```

`front_page` 是 Algolia 维护的「当前首页」标签，**语义正确且永不过期** —— HN 首页本身就是编辑挑过的热门。绝对时间戳方案虽然也能跑，但每天都会过期，属于主动新增技术债。

**教训：第三方 API 的文档语法可能是错的、或者根本没写。一个 400 不等于你的 URL 拼错了 —— 探 6–8 个变体再下结论。**

### 坑 9 · 三个 Reddit 源同一秒抓取必被 429

**症状**：三个 Reddit 源里有一个稳定 HTTP 429、`health` 变 degraded，另外两个正常。

**根因**：Reddit 的匿名速率限制按**出口 IP** 计，**同一秒的多个请求会被判定为突发** `[SPEC]` §11.5 坑 9。

**怎么发现**：把三个源的 `next_fetch_at` 同时设成 `now()` → 立刻复现「两个成功、一个 429」（`programming` 成功、`opensource` 成功、**`selfhosted` 吃 429**）；随后只把 `selfhosted` 单独推后 2 分钟 → **立刻 200，抓到 25 条**。这一步把「可能是 Reddit 挂了」的推断变成了事实。

**怎么避免**：把三个源的 `interval_minutes` **错开**，让取数时刻天然分散 —— 本站用 **180 / 210 / 240**：

| 信源 | 原 | 改后 |
|---|---|---|
| `open-reddit-programming` | 同刻 | **180** |
| `open-reddit-opensource` | 同刻 | **210** |
| `open-reddit-selfhosted` | 同刻 | **240** |

**教训：同一 IP 抓同一站点，并发 = 限流。多个同类信源要么错开间隔、要么串行。**

### 坑 10 · `$env:HTTPS_PROXY` 不会自动被 Node 的 `fetch` 使用

**症状**：Node 脚本直连 Reddit 一律超时（**卡在 TLS 握手之前**），但浏览器和 `git` 走同一个代理都正常 → **极易误判成「网络不通」**。

**根因**：Node 24 的 `fetch`（undici）**默认不读环境变量里的代理**。设了 `$env:HTTPS_PROXY` 也不生效 `[SPEC]` §11.5 坑 9。

**怎么发现**：手工验证 Reddit 时一直超时，直到把**两个参数都加上**才通 —— 少任何一个都会得到错误的结论。

**怎么避免**：跑 Node 探测脚本时加两个参数：

```powershell
$env:HTTPS_PROXY='http://127.0.0.1:7897'

```

| 参数 | 作用 | 漏掉的后果 |
|---|---|---|
| `--use-env-proxy` | 让它读 `HTTPS_PROXY` | 直连超时，**误判成网络不通** |
| `--use-system-ca` | 信任本机代理的 MITM 根证书 | **报证书错误，又是一种误判** |

> 框架自己抓取**不受影响**：`EGRESS_PROXY_URL=http://127.0.0.1:7897` 已在 `.env` 里配好，`http-fetch.ts` 会自动代理非 `.cn` 域名。

### 5.2 `urlTemplate` 必须用 `{raw:url}`

**症状**：生成的原文链接变成一串 `%3A%2F%2F` 转义，点开 404。

**根因** `[实测]` `packages/backend/src/sources/json-list.ts` L29–L38：

```ts
/** "{path}" → encoded value, "{raw:path}" → raw value. Returns null when a referenced value is missing. */
export function renderTemplate(template: string, item: unknown): string | null {
  const out = template.replace(/\{(raw:)?([^}]+)\}/g, (_m, raw: string | undefined, path: string) => {
    ...
    return raw ? String(v) : encodeURIComponent(String(v)).replace(/%2F/g, "/");
  });
```

**规则**：`{字段路径}` → 走 `encodeURIComponent`（只把 `%2F` 换回 `/`）；`{raw:字段路径}` → **原样插入**。

**所以**：已有完整网址时用 `{raw:url}`；只有 slug 时用 `https://example.com/posts/{slug}` `[实测]` `docs/sources.md` L119。
**注意**：JSON 列表**不会**自动把相对网址补成绝对网址，模板要产出完整的 HTTP(S) 地址 `[实测]` L119。

### 6.3 三个 `.err` 文件


`[实测]` **本案例首次验收时**：`_api.err` **0 B** ✅ · `_web.err` **0 B** ✅ · `_worker.err` **42187 B** ❌ **不是 0**。


`[实测]` **首次验收时**该文件有 **495 行**，内容只有两类：
**372 次** `[pg-boss] { type: 'UnknownError', message: 'Non-Error exception', stack: '' }`；**13 次** `message: 'timeout exceeded when trying to connect'`（栈指向 `pg-pool/index.js:45` → `pg-boss/dist/db.js:98`）。

`[已确认]` **两类内容都是 pg-boss 调度器的噪声，不是业务故障。** 它由**启动期 PostgreSQL 还没就绪时 pg-boss 反复重连**产生，与行业内容无关；站点功能始终正常（`_worker.log` 有 `worker started`，`_api.log` 有 `Server listening`，首页 200）。

`[实测]` **复查四站（10-13 20:54，用 `FileShare.ReadWrite` 共享读，避免撞上 worker 的写锁）**：

| 站 | `_worker.err` | 行数 | `Non-Error exception` | 业务类错 |
|---|---|---|---|---|
| AIHOT | **0 B** | 0 | 0 | 0 |
| CryptoHot | **9818 B** | 132 | 101 | 3（均为 pg-boss `timeout exceeded`） |
| AcadHot | **0 B** | 0 | 0 | 0 |
| OpenHot | **1638 B** | 22 | 21 | 0 |

**结论**：`[pg-boss] { type: 'UnknownError', message: 'Non-Error exception', stack: '' }` 是**调度器的良性噪声，不是故障**。它**随运行持续累积，重启会清零后重新累积** —— 本案例的 42187 B 是 10-12 首启到重启前的累积；10-13 19:01 重启后重新累积到 1638 B。

**注意它不是「四个站都有」**：复查时 AIHOT 与 AcadHot 是 **0 字节** —— 出不出现取决于该站启动时有没有撞上数据库竞态。

**真正要看的是同一文件里带业务语义的行**（`report failed` / `timeout exceeded` / 连接错误）：本案例 CrashLoop 类的真故障一条都没有。


`[实测]` 正常日志形如 `_worker.log` = `{"level":"info","msg":"worker started","pid":25768}` · `_api.log` = `{"level":30,...,"msg":"Server listening at http://127.0.0.1:3031"}` · `_web.log` = `{"level":"info","msg":"web started","port":3030,"pid":14944}`。`_worker.log` 里还有一条**正常告警**（不是错误）：`{"level":"warn","msg":"alert (not sent: FEISHU_INTERNAL_ENABLED is off)","title":"🔴 今天的日报还没生成", ...}` → 见 §7 故障 4。

|---|---|---|---|
